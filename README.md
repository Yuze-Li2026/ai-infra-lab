# AI Infra Lab

AI Infra Lab 是面向中文学习者的 AI 基础设施学习工作台。它把原始课程、先修关系、工程实验和个人成果记录连接起来，支持在线访问和本地运行。

[打开工作台](https://yuze-li2026.github.io/ai-infra-lab/) · [阅读文档](docs/index.md) · [查看发布版本](https://github.com/Yuze-Li2026/ai-infra-lab/releases)

**全站共有 11 项实验入口：6 项本地实验、5 项原课流程。** 1.0 正式版支持在线学习、中文导读、个人记录与备份、本地实验运行和报告，以及原课源码准备与检查工具。每项入口的具体内容见下方[学习与实验](#学习与实验)，支持的环境与证据见[首版支持范围](docs/delivery-checklist.md#首版支持范围)。高级实验按实际环境标注验证状态，不作为已经验收的能力。

## 这个项目适合谁

适合希望从编程、数学和系统基础逐步进入 AI Infra 的中文学习者，也适合已有基础、想补齐某个工程方向的人。AI Infra 指支撑模型训练和推理的软件与计算系统，包括框架、GPU、通信、编译器、数据、调度和可靠性等。本站按实际依赖组织学习，已有能力可以用作品和解释复核，不必从头重学。

本站的价值是把成熟资料连接成可执行的学习路径：告诉你先学什么、原作读哪些部分、做什么实践、怎样检查成果。原理讲授以原课程、教材和官方文档为主；中文导读帮助理解和衔接，保留作者、原文、版本与许可。资料和学习路径的选择依据见[原作者路径对照](docs/path-evidence.md)与[能力覆盖矩阵](docs/coverage.md)。

## 开始使用

### 直接在线学习

直接[打开在线工作台](https://yuze-li2026.github.io/ai-infra-lab/)即可阅读中文学习说明、选择任务和记录成果，无需安装或注册。知识点的“打开中文学习指南”直达对应选章与复核任务，原课和官方文档保留为深入学习的入口。

1. 在“我的学习”选择“打开第一个任务”；已有基础时，选择“按工程方向选路线”。
2. 查看“本次学到哪里”，读中文指南，再阅读主资源的指定部分。遇到知识缺口，再回到对应先修。
3. 按任务实践并写下代码位置、检查结果和自己的解释。尚未完成可“记录为学习中”，完成后“提交成果记录”。
4. 用顶部“备份进度”保存记录。进入下一项任务后，继续同样的学习、实践与复核过程。

手机可以阅读和记录，编程与实验通常在电脑完成。英文原作可以用浏览器翻译辅助，代码、公式和重要术语仍需对照原文。第一次遇到文件、终端或 Python 时，跟着[从第一个文件开始](docs/getting-started.md)操作即可。

### 需要本地使用或做实验时

从[源码仓库](https://github.com/Yuze-Li2026/ai-infra-lab)选择 Code → Download ZIP，解压完整源码。目录里应有 `package.json`、`start.cmd`、`site`、`labs` 和 `docs`。安装 Node.js 22 或更新版本后，Windows 用户双击 `start.cmd`，也可以在这个目录的终端运行：

```sh
npm start
```

打开[本地工作台](http://127.0.0.1:4173)。普通浏览和构建无需安装 npm 依赖，无需账号或商业 AI 服务。页面根据先修关系推荐任务；学习记录保存在当前浏览器，通过“备份进度”和“恢复备份”迁移。第一次做实验请阅读[入门教程](docs/getting-started.md)。

保持启动窗口打开，结束本地服务时在终端按 Ctrl+C。不要直接双击 `site/index.html`；浏览器的本地文件限制会影响资源读取。本地工作台与在线网站的学习记录相互独立，需要用备份迁移。

| 你现在要做什么 | 需要准备什么 |
| --- | --- |
| 在线读资料、选任务、记成果 | 现代浏览器，无需 Node、Python、账号或云服务器 |
| 本地打开工作台 | 完整源码和 Node.js 22+，无需先运行 npm install |
| Indoor Voice、对象模型 | Node.js 与 Python 3.10+，无第三方 Python 包 |
| DBDB、共识、micrograd | 按各实验指南创建独立 Python 环境；micrograd 需要 PyTorch，可使用 CPU 版本 |
| 单卡 GPU 或高级原课 | 按具体指南核对设备、系统、依赖与预算，到该任务时再准备 |

源码归档不含已安装的环境、大模型或完整教材镜像。不要在入门时一次安装所有高级工具。

第一项 Python 练习完成后，在项目目录检查你自己编写的文件：

```sh
node scripts/lab.mjs indoor ./indoor.py
```

先读 [Indoor Voice 原题与操作步骤](docs/getting-started.md#2-完成第一项编程练习)，并把路径换成自己的程序。检查结果会写入 `artifacts/`；按输出定位错误，不要手改报告。运行器以当前用户权限执行代码，只运行自己信任的程序。

## 学习与实验

共同起点包含编程、数学、系统与模型基础，随后可按目标进入训练与大模型系统、推理与服务系统、平台与可靠性、数据与模型生命周期、内核与编译器、边缘与异构等方向。每条路线的先修和代表性作品见[按工程方向选择路线](docs/learning-paths.md)。

- 45 个学习模块细分为 198 项选读任务，连接 65 项原始来源。每项知识有原文、章节、复核要求和环境条件，见[逐项知识清单](docs/knowledge-index.md)、[覆盖矩阵](docs/coverage.md)与[学习路径依据](docs/path-evidence.md)。
- 11 项实验入口均有专用指南，分为以下两类。入口数量不等于课程作业数、测试案例数或已经验证的硬件种类。
- **6 项本地实验**：Indoor Voice、对象模型、DBDB、micrograd、共识模拟、单卡 GPU。支持运行与报告；参考复现和自己的实现分别记录，参考报告不计个人作品通过。
- **5 项原课流程**：CS50 最终项目、OSTEP MapReduce、DLSys Needle、MIT Raft、CS336 系统作业。提供源码准备与检查入口，其中当前工具接入 DLSys HW0–HW2、CS336 A1/A2。环境、固定版本和命令见[原课工作流程](docs/project-workflows.md)；各部分的实际验证状态单独列出，课程 TODO 由学习者完成。
- 学习说明、草稿和报告摘要可以备份恢复。本人提交表示留下了成果记录，不构成独立能力认证。

GPU 与系统实验需要相应的本地工具和硬件，网站不远程执行代码。完整原课、多卡、跨机集群及生产服务仍须按各自条件验证；具体状态见[交付清单](docs/delivery-checklist.md)和[验证记录](docs/verification.md)。

[按实验准备环境](docs/environment-preparation.md)解释每项实验需要的工具、执行位置、成功标志和常见错误。[个人云端实验室](docs/private-cloud.md)提供独立 JupyterLab 与 SSH 配置教程；开源代码不包含任何人的实例凭据。个人实例配置与 GPU 课程验收仍需实际设备；免费 CI 和私有交互环境分别记录。

## 数据、费用与云端环境

学习记录保存在当前浏览器，不上传到本站服务器，也不会自动跨设备同步。换浏览器、换地址或端口、使用无痕窗口、清理浏览器数据前，请先“备份进度”；另一台设备用“恢复备份”继续。备份包含成果记录和报告摘要，原始代码、完整实验报告与作品文件需要另行保存。存储出错时先导出备份，不要先清空数据。详情见[数据保存与恢复](docs/getting-started.md#4-保存你的学习数据)。

本站核心功能免费，不要求商业 AI 或订阅。外部课程保留各自访问规则，网络、硬件和自选云算力的费用由使用者自己的环境决定。网站不会替你租服务器或购买服务。

云服务器用于需要远程设备的实验，阅读这个网站无需租云服务器。本站是静态学习工作台，网页不会直接运行你的 Python 或 GPU 程序。“复制”只复制命令，实验在你主动选择的本地或私有环境运行。每个人独立配置并管理自己的资源，没有向访客共享所有者的私人算力；密钥不能放进公开仓库。高级环境先查看[验证状态](docs/advanced-labs.md#环境验证状态)，再按指南配置访问、保存作品和确认停机。

## 遇到问题怎么办

| 现象 | 先检查什么 |
| --- | --- |
| 本地白屏、目录打不开 | 使用 `npm start` 输出的地址，确认完整源码和 Node 版本，避免直接打开 HTML |
| 提示找不到 Python 或依赖 | 核对解释器版本与当前实验环境，按[环境指南](docs/environment-preparation.md)逐项准备 |
| 学习记录不见了 | 回到原浏览器和原地址，或恢复导出的备份；先保留现有数据 |
| 参考程序通过但阶段没完成 | 参考复现不算个人作品；还需要独立实现、知识说明与完整报告 |
| GPU 或原课检查无法执行 | 核对该实验的实际设备、版本和验证状态，不把跳过视为成功 |

更多情况见[常见问题与故障定位](docs/faq.md)。仍无法解决时，在[仓库 Issues](https://github.com/Yuze-Li2026/ai-infra-lab/issues)说明版本、操作步骤、预期结果、实际报错及系统环境，附必要的脱敏日志。不要公开个人备份、密钥或受课程政策限制的答案；安全问题按[安全政策](SECURITY.md)处理。

## 以后怎样交给 AI 维护

把项目目录交给能读文件和运行检查的 AI，并说：

```text
先读项目的 README.md 和 AGENTS.md，按仓库规范继续优化，完成验证并更新下一轮交接。
```

有具体想法时，接着用自己的话说明即可，不需要另备提示词文档，也不需要转发以前的对话。`AGENTS.md` 和[AI 维护流程](docs/ai-maintenance.md)规定资料、界面、实现、验证、发布与交接要求；[验证记录](docs/verification.md)和[交付清单](docs/delivery-checklist.md)保留实际结果与后续工作。每次维护结束，AI 都须更新这些记录，让下一位接得上。新使用者的权限按自己的实际授权确认。

## 维护与验证

AI 接手从仓库根目录 `AGENTS.md` 和[AI 维护流程](docs/ai-maintenance.md)开始；学习者可以直接描述改进想法。`npm run maintenance:status` 离线查看当前源码及报告是否过期，不安装依赖或发布网站。

维护者在项目目录安装固定开发依赖，并按[环境指南](docs/getting-started.md)准备 Python 3.12、CPU 实验依赖和 PyTorch：

```sh
npm ci --ignore-scripts
npm run check
```

完整检查覆盖目录、文档格式、链接、知识覆盖、实际实验、构建和发布文件校验。缺少实验依赖或出现跳过，不能作为完整验收通过。`LAB_TEST_PYTHON` 可以指定测试解释器的完整路径。

这部分供维护者操作，普通学习者不必运行检查才能使用网站。支持范围与高级环境分别验收，不能用首版发布代替所有课程或设备的验证。

界面变更使用 `npm run test:browser`，检查学习、备份、恢复、报告、站内文档、键盘、手机布局和无障碍规则。需要已安装的 Edge（Windows 默认）或 Chrome；可用 `LAB_BROWSER_PATH` 指定。脚本启动独立测试服务，结束后关闭，不自动下载浏览器。

仅检查静态网站与构建：

```sh
npm run check-site
```

输出位于 `dist/`，包含逐文件 SHA-256 清单。构建保留上一份输出，个人数据、实验环境和工作目录不进入公开网站。联网检查资源入口使用 `npm run check-links`；超时和访问限制需复核，不能直接判为资源失效。
