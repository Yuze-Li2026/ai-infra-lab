# 0.4.1 实际可用性审查

日期：2026-10-09。本文记录 0.4.1 发布时的检查。后续验证分支已在 Ubuntu 实测 DLSys HW0/HW1/HW2 与 MIT Raft 环境，见[最新验证记录](verification.md#linux-原课环境)；下文的本机限制和测试数量保留为该版本的历史事实。

审查问题是“学习者能否真正执行、提交和复核自己的作品”，而不是页面有没有按钮、参考程序能否通过。本轮确实发现缺口并修复。原先 0.4.0 的自动测试没有证明 GPU 独立提交或五项原课完整流程已经存在。

## 发现的实质问题与修复

| 原问题 | 具体修复 |
| --- | --- |
| GPU 只能运行参考程序，无法验收自己的实现 | 增加七个明确接口和 `--submission`，实际调用用户文件；CPU oracle、真实 MSE、模型/优化器/RNG/步数及下一步由检查器验证 |
| 五个高级课程卡片只有外部入口 | 全部接入[原课准备和测试指南](project-workflows.md)，提供版本锁、计划、起始源码获取、环境隔离与实际检查 |
| DLSys 安装路径不明确 | 核对原 notebook，发现 mugrade 不在 PyPI；固定教师仓库提交，真实安装独立 CPU 环境并执行原 pytest |
| CS336 可能复用不兼容的 GPU 环境 | 读取当前原项目 pyproject，明确 PyTorch 2.11 与本地 2.10 分开；没有课程环境时明确失败，不隐式下载依赖 |
| MIT 旧版路径可能不适用于 2026 实验 | 实际获取官方 2026 源码；使用 `src/raft1` 和原 `make raft1`，保留 Linux/WSL2 与 Go 条件 |
| 从其他目录调用实验入口会找错源码/环境 | 入口用脚本位置定位项目，先解析用户作品与输出路径；不再依赖调用者正好处于项目根目录 |
| Indoor 多余参数会被静默忽略 | 拒绝额外参数；解释器通过 LAB_PYTHON 明确指定，修正入门说明 |
| 手动复制 GPU 模板遇到已存在目录时，部分 shell 可能继续复制 | 提供跨系统 `--init` 独占创建，已有目录/文件拒绝覆盖；实际验证原作品字节保留 |
| 旧 Python 与缺少输出参数导致诊断异常 | 先检查 Python 版本，再加载版本元数据；用 argparse 检查参数，并记录包实际导入与 GPU 版本条件 |
| 课程超时可能遗留测试子进程 | 限定每次启动的进程树，超时或中断时清理；原始日志和每次独立 JUnit 文件不与旧结果混用 |
| 恢复检查只比较输出，可能漏掉优化器配置 | 恢复前扰动优化器学习率和 RNG，比较完整优化器状态及实际下一步；CPU/GPU 标量计数器按值核对 |
| Windows 偶发拒绝刚复制完的构建/课程目录重命名 | 限定范围、有限重试；课程交付每次重查目标，拒绝覆盖；构建最终失败继续回滚并保留旧构建，不删减完整性检查 |
| 英文 Windows 的默认字符编码无法打印中文课程计划 | 课程工具标准输出和子进程日志明确使用 UTF-8；增加 cp1252 环境回归，并核对 Windows/Linux CI 实际结果 |

## 实际执行的证据

1. 六项本地实验继续运行原测试和补充检查；对象模型 28、DBDB 21、共识 46、micrograd 11。GPU 当前四类共 7 个案例在 RTX 5060 Laptop 上实际运行。
2. GPU 验收另执行 6 组程序：正确参考路由、错误矩阵乘积、错误梯度、伪造训练 loss、遗漏优化器状态、遗漏 RNG 状态。正确路由通过，五种错误按对应检查拒绝；作品文件没有被改写。参考路由用于检查执行器，不证明学习者独立完成。
3. 原课准备工具实际交付八个独立工作目录：CS50 空项目、DLSys HW0/HW1/HW2、CS336 A1/A2、OSTEP 原 API/README、MIT 2026 源码；各自提交/归档指纹核对通过。第三方课程源码与个人作品留在忽略发布的 `workspaces`。
4. DLSys 原测试真实执行：HW0 收集 6 项、HW1 收集 29 项、HW2 收集 93 项，无跳过；起始未实现代码分别失败 6、29、91 项。少量原始辅助代码通过不代表作业通过。日志和 JUnit 保留在本地，不把 TODO 失败伪装为环境不兼容或完整复现。
5. CS50 校验用临时夹具实际执行三项 pytest，改错函数后产生真实失败。目录重复准备不会覆盖原文件；坏归档在交付前被拒绝。夹具只是运行器验证，不是课程项目答案或学习成果。
6. OSTEP 的补充客户端在本机 gcc/pthread 工具链上实际编译；故意空实现即便退出码为 0，六类行为检查仍拒绝。尚未完成自己的 MapReduce 库，不能声称通过了原作者完整评分或内存检查。
7. 五项新增自动回归分别覆盖计划、作品保护/坏归档、实际学生测试、异目录入口和超时子进程清理。整套自动检查按实际输出记录，不以跳过替代通过。

完整检查第一次在受限 Windows 沙箱中遇到临时目录、realpath 和 fissix 缓存访问权限失败；在已授权项目范围的执行权限下重跑原 29 项全部通过。后续增加超时回归形成 30 项，以当前 CI 和本地结果为准；没有把权限失败计为通过，也没有为隐藏失败删减测试。

## 界面与文档怎样复核

11 个实验卡片均能打开对应站内指南。参考复现、本地检查和原课准备流程分别标注；课程计划命令不算“已完成原课”。新增浏览器检查读取真实 GPU 程序生成的通过和失败报告，验证导入、备份与状态；对 320/390/768/1280 屏宽复查长命令、表格和按钮，保留桌面/移动截图。其余已有学习、记录、备份、安全阅读和报告回归继续执行。

在线网站负责学习导航、文档与个人记录。本地训练、编译与课程测试在自己的机器/课程环境运行，需要下载本站源码；网站没有远程执行任意代码的后端。源码获取方式见[从第一个文件开始](getting-started.md)。

## 哪些仍未被实测证明

MIT 原源码获取已验证，但当前本机没有 Linux/WSL2 和 Go，尚未跑完整 Raft。CS336 A1/A2 的独立 PyTorch 2.11 环境尚未安装，完整原作业未执行；A3–A5 与 DLSys HW3/HW4 尚未接入执行工具。vLLM 服务、MLIR、真实 Kubernetes/Ray 集群、多卡 NCCL、设备与长期生产负载也没有因文档齐全而自动完成。

这些方向的原课/官方入口、先修、目标、硬件和验收范围在[高级原课](advanced-labs.md)、[学习路径](learning-paths.md)、[覆盖矩阵](coverage.md)中保留。当前结果是可以实际执行的学习平台与明确的课程工作流程，**还不能称所有高级工程方向均已完成运行验证**。真实课程答案、训练预算、独立设计和验收仍由学习者完成。

## 复查命令与版本证据

```sh
npm run check
node tests/gpu-check.mjs
node tests/usability-browser.mjs
```

浏览器检查使用项目已有 Playwright 和 Edge，需设置 `LAB_PLAYWRIGHT_ROOT`、`LAB_BROWSER_PATH`，不安装浏览器。GPU 检查需要已准备并授权的 PyTorch 2.10.0+cu128。原课工具的 `plan` 不改变机器；`prepare` 不安装依赖；`check` 使用自己的课程环境并写执行证据。

公开同步、同提交 Windows/Linux 验证及 Pages 状态以[仓库 Actions](https://github.com/Yuze-Li2026/ai-infra-lab/actions)为准；0.4.0 的归档是历史快照，不会覆盖其标签或附件。后续每个发布提交仍需通过完整 Validate 后才允许部署。
