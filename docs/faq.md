# 常见问题与故障定位

先保留报错原文与复现步骤，修改前备份学习数据。诊断按“观察 → 最小复现 → 修复 → 再验收”进行，不通过重装一切掩盖原因。

## 我完全不会编程，先做什么？

打开“我的学习”的第一项任务，先认识文件、编辑与运行，再使用主资源学习。算术可以与 Python 起点并行。不要从 GPU、多卡或模型服务开始，不必先安装所有工具。[从第一个文件开始](getting-started.md)逐步说明操作。

## 网站或实验是否收费？

本站核心无需登录、商业 AI 或订阅，可本地运行。原始资源保留各自访问条件。Python/PyTorch 软件安装本身不购买商业服务；网络、电力、存储或另行租用算力由实际环境决定。平台不自动购买云资源、下载模型或修改驱动。

## 双击 HTML 后为什么没有资源？

浏览器的本地文件限制阻止目录请求。Windows 使用 `start.cmd`，其他系统在项目目录运行 `npm start`，访问终端输出的 loopback 地址。先执行 `node --version`，最低 22。不要把 Python 程序粘贴到 PowerShell 命令行执行。

## 端口占用、白屏或找不到模块

端口占用时保留原服务，PowerShell 设置 `$env:PORT=4174` 后启动，访问新地址。不同端口是不同 origin，原学习记录要先备份再恢复。白屏时检查 HTTP 服务、`catalog.json`、浏览器控制台和 Node 版本；完整源码包含 `site/vendor`，无需为启动运行 npm install。模块缺失应恢复完整源码，不从不明站点下载同名文件。

## Python 有多个版本，实验选中了哪一个？

`node scripts/lab.mjs` 优先选择项目 `.venv-labs`，也可使用 `LAB_PYTHON` 指定。运行该解释器的 `scripts/doctor.py` 查看实际路径、版本、依赖与 GPU。最低 Python 3.10，推荐 3.12；创建 venv 前核对版本，不用旧 3.6 环境安装新版实验依赖。

## 实验失败了，如何查看原因？

检查控制台和 artifacts 中的 JSON：`mode`、`commit`、`passed`、各测试的 `error / details`。运行器会在已进入检查流程后记录失败。若命令参数、解释器或作品文件无效，可能在生成报告前退出，此时以本次控制台错误为准，不读取旧报告当成本次结果。确认文件/包路径、依赖、公共接口和原始文件校验；不要改原断言让错误通过。独立作品放在自己的目录，upstream 保留原样。

## 为什么 GPU 或原 PyTorch 对照没执行？

CUDA GPU、驱动兼容和正确的 PyTorch 构建都需实际检查。系统看到显卡不等于 torch 可执行；无 CUDA 时 GPU 检查失败，micrograd 没有 PyTorch 时两项原对照明确不执行。没有 NVIDIA 的电脑仍可使用 CPU PyTorch 学习自动微分。Windows GPU 锁不能直接用于 Linux/macOS。安装条件见[GPU 指南](gpu-lab.md)，不自动改驱动。

## 参考代码通过后，为什么阶段还没通过？

参考运行只证明集成环境可用。阶段需要本人知识说明、当前版本独立提交模式的通过报告，以及设计、边界案例、测量协议与解释。“材料齐备”也不等于独立认证。真实评审可以要求现场修改程序与解释失败案例。

新版还核对规定测试组与数量。对象模型必须包含四阶段 28 项；单阶段或只有总体计数不能计入完整作品。旧备份仍保留，旧摘要没有测试范围时重新导入原 JSON，或用当前运行器复验。不要用 `-O` 或 `PYTHONOPTIMIZE` 移除原测试断言。

## 为什么报告不能导入？

必须选择对应实验，文件小于 1 MB；实验标识、固定版本、模式、日期和整体/各测试结果应一致。不要手改报告的 passed 或 mode。重新用本版运行器检查自己的代码并导入新文件。保留完整报告；页面只保存摘要与 SHA-256 指纹。指纹不是真实性签名。

## 学习数据、草稿和报告去哪了？

数据保存在当前浏览器和网站 origin；端口、网址、浏览器、设备或无痕模式变化会形成另一份存储。草稿暂存于当前标签页会话，不能代替备份。原始代码与完整实验报告是本地文件，不会被学习备份自动打包。关闭、清理存储或换设备前导出 JSON，并另外备份作品。

## 恢复失败或浏览器提示存储满

合法学习备份上限 2 MB，版本与节点必须兼容，未来时间明显超前会拒绝。存储失败时页面明确显示尚未保存，仍可导出内存中的记录。损坏原数据不会在普通保存时被覆盖；主动恢复合法备份会保留损坏原文副本。不要先清空存储再尝试恢复。

## 英文资源、失效链接与版权

先读中文导读，再携术语与具体问题读原文。社区译文未逐句人审，不能当官方译文。403、429、超时和连接错误需与真正 404 区分；使用链接检查分类，记录日期。教程文字、代码、视频、数据和模型分别核实许可；本站 MIT 不覆盖第三方权利。

## 性能结果比参考差，是不是做错？

先验正确性，再核对环境、种子、输入规模、预热、样本和测量边界。更少内存可能以更慢读取为代价；GPU 计时是否包含传输会改变结论。报告完整样本与失败的优化，不能只留最快一次。不同设备之间没有承诺相同数值。

## 如何反馈一个问题？

在仓库 Issues 描述目标、操作步骤、期望、实际、系统和版本；附最小代码或脱敏日志。不要上传课程受限答案、完整学习备份、访问令牌、未知模型或个人数据。安全问题遵循[安全政策](../SECURITY.md)，不要在公开 issue 暴露漏洞利用和秘密。
