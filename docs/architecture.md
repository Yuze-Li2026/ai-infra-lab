# 产品架构与选型记录

状态：2026-10-09，完整本地学习链；选择可被后续实验推翻。

## 产品边界

核心体验是学习工作台：下一项任务 → 原资源与先修 → 实验与成果 → 本地记录 → 继续。首页不堆放整份研究报告；地图、资源目录与实验按需打开。核心可静态托管，不自动运行外部代码，不依赖商业 AI、账户或后端数据库。

|候选方案|研究入口|价值|初版决定与理由|
|---|---|---|---|
|MkDocs|[官方文档](https://www.mkdocs.org/)|成熟静态文档系统，适合维护长文|后续维护文档站候选；工作台进度和交互仍需补充代码，当前不额外要求 Python 构建环境|
|JupyterLite|[官方文档](https://jupyterlite.readthedocs.io/en/stable/)|浏览器 Notebook，降低部分实验配置门槛|保留为 CPU 教学实验候选；不能替代本机 CUDA/系统调用/多卡实验，需单独评估包与资源体积|
|Mermaid|[官方文档](https://mermaid.js.org/)|成熟声明式图表工具|长文图表候选；当前图只有 24 节点，交互以原生分阶段依赖列表实现，避免引入渲染包。节点量增长后重评图布局工具|
|uv|[官方文档](https://docs.astral.sh/uv/)|Python 项目与环境管理|未来本地实验锁定工具候选；入门与对象模型无第三方依赖；其他实验在独立环境安装固定的小型依赖，不要求新手先装多个管理器|
|HTML/CSS/浏览器 API + Node 标准库|本地 Node v24.21.0；目标 Node 22+|可直接运行，静态输出，不需要在线依赖|用于学习工作台；只原创已有方案未覆盖的目录组织、推荐和成果记录连接逻辑|
|服务器应用框架 / Sites 托管 starter|静态托管方案比较|后端能力、托管工作流|当前目标优先 GitHub Pages；核心体验无需后端框架或托管账号绑定|

这是范围与维护成本的决策，不是断言这些工具优劣。还需进一步比较文档国际化、资源索引、长期学习记录与无障碍图工具；本轮没有宣称对全部工具生态完成调研。

## 数据与模块

- `site/catalog.json`：唯一资源、阶段、知识与实验数据源。`scripts/create-catalog.mjs` 仅用于初版生成，不要日常运行覆盖已审阅目录。
- `site/core.js`：纯数据状态逻辑、先修推荐与备份校验；同一套逻辑在页面和测试中使用。
- `site/storage.js`：写入前重读合并、损坏记录保护与主动恢复时的原文副本保存；存储失败明确交由界面提示。
- `site/app.js`：导航、过滤、事件与持久化协调；`site/views.js` 集中生成页面，所有用户文本转义。
- `scripts/validate.mjs`：字段、引用、依赖无环及评估完整性校验。
- `scripts/serve.mjs`：仅绑定 loopback，允许指定公开文档与网站文件，拒绝越界解析；不充当生产服务器。
- `scripts/grade.mjs`：主动 CLI 执行学习者指定程序，超时与输出限制、JSON 报告；不具有安全隔离能力。
- `scripts/build.mjs`：校验后在独立目录构建公开文件，生成 SHA-256 清单；保留旧输出后切换到 `dist/`，失败保留恢复材料。拒绝符号链接输出路径，防止越界。
- `labs/object-model/run.py`：适配固定版本的 AOSA 原测试，四阶段各用独立进程；提交模式与参考测量严格区分。
- `schemas/catalog.schema.json`：资源维护的编辑器契约；运行时校验器补充跨记录约束。

进度保存在 `localStorage`，版本字段为 1。成果记录包含节点、状态、说明和时间，明确为本人提交。备份拒绝无效节点和异常未来时间，恢复合并同节点较新记录。草稿暂存在 `sessionStorage`，刷新可恢复，导出时加入备份。个人记录不会上传。不同 origin 的存储不能互相读取，需 JSON 导出迁移。

支持 Web Locks 的浏览器会串行化多个标签页的“读取—合并—写入”，防止同时保存覆盖其他节点。不支持时退回写入前重读合并，无法保证真正同时写入的原子性。同一节点同时编辑仍按更新时间决定；重要说明应导出备份。

路由采用 hash，资源使用相对地址，适配 GitHub Pages 仓库子路径；不需要重写规则。构建将研究文档复制到公开输出，不包含原提示词、测试样例、学习者代码或成绩报告。重构构建时必须重新检查白名单。

## 验证与局限

单元测试检验真实失败边界：依赖环、无效引用、空成果、未知备份版本、错误与超时提交。浏览器验收检查导航、成果保存、刷新、备份、恢复、恶意文本显示和窄屏。`npm test` 不是课程实验通过记录。

浏览器若支持 WebMCP，页面仅注册只读 `get_learning_plan`；不暴露隐含完成操作。没有支持环境时此增强不影响平台。外部链接健康在网络不通时标为未知，不伪造访问成功。

规模扩大时，可将资源 JSON 拆为可独立维护的声明式模块，并迁移进度版本；暂不开放任意第三方代码插件。应先证明维护收益，再添加数据库、账户同步或图布局引擎。

## 站内阅读与报告

成熟 Markdown 渲染组件 Marked 18.1.0（MIT）与 DOMPurify 3.4.16（Apache-2.0 许可副本保留）替代自行写 Markdown 解析与 HTML 清理。site/vendor/manifest.json 保存版本和逐文件 SHA-256，构建核验并只复制清单内文件。site/documents.js 管理本地文档允许列表、内容清理、安全链接与目录焦点；不允许任意远程 HTML 插入。

site/reports.js 管理报告一致性校验、备份摘要与阶段材料条件；只保存结构化摘要和文件指纹。参考模式不计入独立作品，当前版本检查通过也不能证明作者独立性。核心 records 与新增 labReports 独立按时间合并，兼容旧备份。
