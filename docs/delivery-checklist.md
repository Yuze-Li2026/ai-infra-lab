# 工程交付验收清单

基线：0.4.1，提交 `cca5181`。本清单落实追加提示词的要求；未完成项保持开放，不以历史版本的通过结果替代。适用对象为平台维护者和发布审核者。

## 交付范围

包括学习工作台、45 个知识节点与来源依据、全部实验入口、声明式扩展、文档阅读、学习记录、备份恢复、本地运行器、固定课程源码准备、构建、持续验证和发布恢复。既有学习路径和实验保留，缺少运行证据的高级环境继续列入验收。

课程中的独立实现由学习者完成；平台必须提供可执行的准备与检查流程。原始作业的未实现失败、环境错误和实现错误分别记录，不以复制答案完成课程验收。

## 必须核对的证据

| 编号 | 验收条件 | 证据与当前工作 |
| --- | --- | --- |
| Q01 | 正常和失败操作均可用，个人数据不丢失 | 浏览器任务、备份、损坏数据、并发与存储失败回归 |
| Q02 | 运行器受控退出，正确结果与错误实现可区分 | 真实进程、超时、输出上限、UTF-8、错误提交和退出码 |
| Q03 | 原课准备、环境和测试确实执行 | 固定源码指纹、原始命令、测试收集、执行日志与环境记录 |
| Q04 | 第三方依赖可复现且经过审查 | 版本锁、许可证、源码校验、依赖审计与升级记录 |
| Q05 | 文档清楚准确并与代码一致 | 写作规范、格式和链接检查、接口参考、命令执行记录、逐份审校 |
| Q06 | 桌面和手机可操作 | 键盘导航、自动无障碍检查、四屏宽、文本放大、实际截图 |
| Q07 | 部署可追溯并能恢复 | 同提交 CI、构建清单、归档恢复、线上文件校验、回滚步骤 |
| Q08 | 知识与实验范围有外部依据 | 覆盖矩阵、原课程与官方文档、先修、成果要求与维护日期 |

自动检查、人工式审校和环境验证分别保留结果。测试数量只用于复核执行范围，不作为质量或完整性的替代指标。必须补齐 Q01–Q08 的证据后，才允许把本轮交付标为通过。

## 环境与尚待解决的条件

本机已有 Windows、Node、Python 3.12、单卡 CUDA 与 MinGW。尚未安装 Linux/WSL2、Go 和 CS336 的独立 PyTorch 2.11 环境。先使用已有条件完成平台、CPU 与单卡检查；跨系统课程验证可使用仓库 Linux CI。新增大规模下载、付费算力或系统配置须按具体方案获得授权。

`Original course Linux environments` 是单独的工作流，可手动触发，也在 `codex/quality-and-ui` 验证分支的相关文件变更时执行。它在标准 Ubuntu runner 内安装课程依赖、编译 HW0 扩展并执行固定版本原测试，分别核对环境可运行与未实现作业仍失败，不能替代学习者通过作业。新增工作流只有在远程真正执行后才构成 Linux 证据；未执行或失败时，本项仍未完成。

真实多卡通信、Kubernetes/Ray 集群、完整推理服务、编译器后端以及全部原课作业仍在范围内，但不能由本地小规模测试证明。每项需明确设备、安装、运行和验收条件；没有相应条件时保留未完成状态，不改成“全部工程已验证”。

## 复核与发布规则

测试失败应保留原始证据并修复原因。禁止删减断言、伪造通过、把跳过算通过，或为发布而降低支持范围。源码、文档与测试变更一起审阅；最终源码提交须同时通过本地检查、Windows/Linux CI 和线上复核。发布产物包含源码、静态文件、验证记录及校验和。
