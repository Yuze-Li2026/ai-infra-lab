# 质量验收与发布门槛

## 平台最低门槛

|方面|通过条件|
|---|---|
|初次使用|不登录、不用商业 AI、不装依赖包即可启动工作台，看到下一项任务|
|知识数据|唯一 ID、已知引用、无循环先修、每资源完整来源与 12 项初评|
|学习流程|查看先修 → 原资源 → 实验要求 → 成果保存 → 刷新可恢复|
|成果语义|学习中、本人提交和独立认证不混淆；不自动宣称通过高级实验|
|备份恢复|导出可重导入；未知版本/节点/过大备份整份拒绝；同节点保留较新记录|
|内容安全|导入文本不执行 HTML；只链接 HTTPS 资源；本地服务器限制文件访问|
|构建部署|离线构建；项目子路径可用；输出不含个人代码/报告/原提示词|
|可访问性|中文文档语义、键盘焦点、状态消息、手机宽度与文本放大可用|
|实验检查|正确、错误、空输入、Unicode 与挂起提交可区分；报告包含真实结果|
|原项目集成|版本与许可固定、SHA-256 完整性、原测试运行、错误独立提交失败、测量协议可复查|
|数据保护|刷新后草稿恢复、备份含草稿、并发写入保护、失败时不声称保存成功|
|维护与恢复|隔离构建、保留旧输出、校验发布清单、保留可追踪的本地版本|

## 阶段能力门槛

从零入口的 Indoor Voice 只是运行和检查流程演示。程序设计阶段需要综合原课程项目；计算系统阶段需要复杂状态、并发和故障测试；框架阶段需要梯度/算子/训练一致性；性能与规模化阶段必须记录硬件、版本、基线、精度、预热、重复测量和解释。

一个阶段真正完成至少需要设计、独立实现、测试、优化或合理解释优化不适用、原理说明、复现材料与评审。本人点击提交不是充分证明，未来独立评审机制仍未实现。

## 报告、文档与发布

报告应匹配实验和固定版本，整体与各检查结果一致；参考报告不计入独立作品。旧学习备份保持兼容，报告摘要按导入时间合并。文档总入口覆盖学习、各阶段实践、维护、安全、研究和验收；构建前自动核对每份 Markdown 接入阅读器、标题和本地链接。

公开部署前需要远程 Windows/Linux 校验通过、Pages 发布任务成功，并实际检查线上子路径、指南、手机显示和临时上下文的备份流程。没有通过的检查明确记录失败或环境条件，不改为已验证。
