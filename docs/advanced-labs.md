# 高级原课实验：环境、产物与验收

本地精选项目构成可运行的学习与验收链；完整大学作业和工业系统属于进一步深化。下列入口是原始课程，**尚未在本机完成这些完整作业**，不会因为列出命令或阅读课程首页就标记为已复现。先完成每个阶段的原理、设计和独立作品，再按方向选择。

五个原课入口现已有[专用准备和测试流程](project-workflows.md)，可以获取固定起始源码、创建个人目录和执行实际检查。源码获取、环境就绪、测试完成与个人掌握分别记录；准备成功不计作业通过。

## 程序设计：CS50 最终项目

[CS50 Python](https://cs50.harvard.edu/python/) 原课提供最终项目要求。先修函数、异常、测试、文件与 Git。按当前原题定义项目范围，在自建目录保留源代码、测试和 README；遵守学术诚信要求，不公开受限制的课程答案。Python 环境独立于平台，固定实际版本和依赖。

验收需有自行设计的真实问题、输入异常与边界案例、测试命令、复现步骤和口头说明。Indoor Voice 是入门检查，不能替代最终项目。测量时说明输入规模与重复次数；测试通过不能代替需求是否真正解决。

## 操作系统：OSTEP 项目

[OSTEP 原书](https://pages.cs.wisc.edu/~remzi/OSTEP/) 与其[原项目仓库](https://github.com/remzi-arpacidusseau/ostep-projects) 是选题入口。先修 C、内存、系统调用、进程与线程。先确认具体项目的 README、许可和所需 Unix API；Windows MinGW 并不等同于完整 POSIX 环境。

建议使用已有 Linux 环境或已具备的 WSL，记录发行版、编译器、构建选项与提交。本站不会自动安装 WSL 或改变系统设置。按原题实现并运行原测试；另外记录竞态、资源释放与失败路径。相同工作负载下重复测量，解释锁竞争、I/O 与调度的影响。提交设计、代码、日志与性能报告；不把 DBDB 的文件锁检查当作完整 OS 实验。

## 张量框架：Deep Learning Systems

[DLSys 原课](https://dlsyscourse.org/) 将数学、机器学习与系统编程连接到框架作业。先修线性代数、梯度、NumPy/数组语义、C++ 与内存布局。micrograd 先验证标量链式法则，再按原课当期作业进入张量、广播、后端、神经网络与优化。

先从原课程仓库确认作业版本、许可证、编译器、CUDA 条件和测试入口；保留上游提交和环境锁，不将作业答案嵌入平台。产物应包含 CPU oracle、广播/形状边界、梯度数值检查、后端正确性、峰值内存和重复性能测量。没有对应 CUDA 编译工具链时，CPU 作业与 GPU 作业分别记录状态。

## 容错系统：MIT 6.5840

[MIT 6.5840](https://pdos.csail.mit.edu/6.5840/) 的原实验按学期维护。先修 Go、goroutine、channel、竞态检测、网络与故障语义。本机当前没有 Go；不以 AOSA 共识模拟器代替原实验。先跟随原实验环境页准备 Go，再固定课程版本并执行其测试与竞态检测命令。

应记录每个场景的随机种子、失败次数、日志和恢复轨迹；不能只运行一次成功案例。产物包含状态不变量、持久化策略、重复请求处理和故障恢复解释。公开范围遵守原课要求与许可。多进程测试仍不等同于跨机部署。

## GPU 与语言模型系统：CS336

[Stanford CS336](https://cs336.stanford.edu/) 提供原课日程与作业入口。先修框架、数值测量、GPU 内存与并行、分布式通信、数据来源和许可。8 GB 单卡能够运行本项目的小型集成检查，但不能据此保证满足原课所有作业的显存、多卡和训练预算。

从具体原作业核对依赖、输入规模和硬件要求，先准备可审阅的版本锁、预计磁盘/显存和费用，再决定安装或租用资源。未经明确授权不购买算力，不下载大模型。测量分别覆盖内核正确性、端到端传输、显存、吞吐、训练质量与多卡扩展；单项加速不能替代完整系统验收。

2026 春 CS336 五项作业可作为训练方向的连续检验，具体要求以原课当期页面为准：

| 原作业 | 本站先修任务 | 独立产物与主要复核 |

| A1 Basics | models、framework、numerics、data | tokenizer、模型、优化与训练；形状、梯度、数据切分、训练曲线与复现 |
| A2 Systems | gpu、profiling、collectives、memory | 内核正确性、显存、同步计时、通信与优化前后端到端结果 |

原课 AI 政策要求自主完成作业，本站只连接资源、先修与验收，不提供作业答案；先核对当期政策。其他方向有独立路线，见[方向学习路径](learning-paths.md)。

## 推理、可靠性与编译器方向

进入这些方向前，可先执行[隔离集群环境](cluster-environments.md)和[CPU 推理与编译器环境](inference-compiler-environments.md)中的复验流程。它们检查真实依赖与系统行为；是否通过以具体提交的实际报告为准，不代替后面的完整方向作品。

- [vLLM 官方文档](https://docs.vllm.ai/en/latest/)：核对 GPU/平台兼容和模型许可证，先预算权重、KV cache 与并发。设计负载、质量基线、TTFT、逐 token 延迟和吞吐，并保留失败请求与恢复。CPU 环境工具使用固定 Qwen3-0.6B；完整 GPU 服务与生产负载另行验证。
- [Google SRE](https://sre.google/sre-book/table-of-contents/) 与 [Kubernetes Security](https://kubernetes.io/docs/concepts/security/)：明确 SLO、权限边界、告警、回滚和恢复。优先在自己的隔离测试环境进行故障注入，不修改真实业务。
- [MLIR Toy](https://mlir.llvm.org/docs/Tutorials/Toy/)：先修 AST、类型、IR 与编译器构建；记录 LLVM 提交、构建条件、语义等价测试和优化前后 IR。IREE 的 CPU 编译流程提供实际产物检查，不能代替 Toy 全课程或 LLVM 源码构建。

## 统一产物清单

每个深入项目均需：原始来源与许可、固定提交、先修诊断、环境锁、设计不变量、独立实现、原测试与额外边界、重复测量协议、失败解释、恢复方案。维护者按[扩展规范](extensions.md)接入，只有实际运行与记录证据之后才能改为已复现。
